# DeeX Baseline Image Build Procedure (Google Pixel 8 — shiba)

## Overview

This document provides the step-by-step procedure for the project owner to execute a baseline AOSP build for the Google Pixel 8 (`shiba`) on a controlled build host.

**Important Reality & Boundary Rules:**
- This procedure builds unmodified upstream AOSP tag `android-15.0.0_r1` plus the device's official vendor binaries, with no custom DeeX security code yet.
- The build must be executed by the project owner on their dedicated build host. No build or image generation occurs inside the AI agent sandbox.
- **Do NOT flash, unlock, or modify hardware partitions** until Chunk 5 (Flash-and-Boot Procedure).

## Step-by-Step Procedure

### Step 1: Prepare the Build Host
1. Verify host hardware against requirements in `build/env/host-requirements.md`.
2. Execute host verification check script from repository root:
   ```sh
   sh tools/check-build-host.sh
   ```
3. If building in container mode (recommended), build or pull the container image defined in `build/env/Dockerfile` and record its container image SHA-256 digest.

### Step 2: Establish the Work Directory Layout
Choose a clean parent directory for all build activity (e.g. `WORK_DIR=/home/owner/deex-work`).
Set `WORK_DIR` in your environment:
```sh
export WORK_DIR="/path/to/your/deex-work"
mkdir -p "$WORK_DIR/src" "$WORK_DIR/out" "$WORK_DIR/logs" "$WORK_DIR/records"
```
Structure layout:
- `WORK_DIR/src`: Synced AOSP source tree
- `WORK_DIR/out`: Build output artifacts
- `WORK_DIR/logs`: Timestamped sync, build, and verification execution logs
- `WORK_DIR/records`: Build records generated by `tools/make-build-record.sh`

### Step 3: Initialize and Sync Source Tree
Run the automated baseline sync wrapper script from the DeeX repository root:
```sh
sh tools/baseline-sync.sh --work-dir "$WORK_DIR"
```
*Primary Source Command Reference*: Underlying wrapper executes `repo init -u https://android.googlesource.com/platform/manifest -b refs/tags/android-15.0.0_r1 --manifest-name=aosp-pinned.xml` and `repo sync -c -j$(nproc)` using `build/manifests/aosp-pinned.xml`.

The script logs all output to `$WORK_DIR/logs/sync-<TIMESTAMP>.log` and verifies afterwards that synced commit hashes match every pin in `aosp-pinned.xml`.

### Step 4: Obtain and Extract Device Vendor Binaries
Follow `docs/build-records/vendor-binaries-procedure.md` to acquire Google Pixel 8 (`shiba`) driver binaries for `android-15.0.0_r1` (`AP3A.240905.015.A2`):
1. Personally accept driver license terms at `https://developers.google.com/android/drivers#shiba`.
2. Download vendor archives (`google_devices-shiba-ap3a.240905.015.a2-*.tgz`).
3. Verify vendor binary checksums using `tools/verify-vendor-binaries.sh`:
   ```sh
   sh tools/verify-vendor-binaries.sh --vendor-dir /path/to/downloads --expected-sha256 <HASH>
   ```
4. Extract the vendor archive self-extracting shell scripts inside `$WORK_DIR/src`.

### Step 5: Configure Build Environment and Target
1. Load build setup scripts:
   ```sh
   cd "$WORK_DIR/src"
   source build/envsetup.sh
   ```
2. Select target device and variant:
   ```sh
   lunch aosp_shiba-userdebug
   ```
   *Target Source Evidence*: `aosp_shiba-userdebug` is the official first-party AOSP target for Google Pixel 8 on Android 15 (Primary Source: AOSP Codenames & Build Numbers, `VERIFIED`).

### Step 6: Execute Baseline Image Build
Run the automated build wrapper script from the DeeX repository root:
```sh
sh tools/baseline-build.sh --work-dir "$WORK_DIR" --config build/configs/development.md
```
Underneath, the wrapper executes `m droid` (or `m`) under development build flags, capturing full log output to `$WORK_DIR/logs/build-<TIMESTAMP>.log`.

### Step 7: Verify Build Output & Artifacts
1. Ensure `tools/baseline-build.sh` returned exit code 0.
2. Confirm the presence of key image artifacts in `$WORK_DIR/out/target/product/shiba/`:
   - `boot.img`
   - `system.img`
   - `vendor.img`
   - `product.img`
   - `system_ext.img`
   - `vbmeta.img`
   - `super.img`
3. If any expected artifact is missing or build exit code is non-zero, consult `docs/build-records/troubleshooting.md`.

### Step 8: Generate Build Record
Run build record generator tooling:
```sh
sh tools/make-build-record.sh --work-dir "$WORK_DIR" --result SUCCESS
```
This produces a dated, uniquely identified record in `$WORK_DIR/records/build-record-<ID>.md` containing image file SHA-256 checksums, durations, host specs, and manifest SHA-256 hash.

### Step 9: Prohibited Actions
- **DO NOT** attempt to flash images to a physical Google Pixel 8 device in Chunk 4.
- **DO NOT** unlock device bootloader or alter hardware partition state in Chunk 4.
- **DO NOT** commit proprietary vendor blobs, private signing keys, or intermediate build build outputs to Git.
